# cmt-manual (CUBRID Migration Toolkit) 전용 리뷰 규칙

저장소 공통 규칙은 루트 `.greptile/rules.md`에 있습니다. 이 파일은 **거기에 더해지는** CMT 매뉴얼 전용 규칙입니다.
(Greptile은 상위 디렉터리의 규칙과 이 파일의 규칙을 **합쳐서** 적용합니다. 덮어쓰지 않습니다.)

---

## 1. 제품 명칭

| 구분 | 표기 |
|:---|:---|
| 정식 명칭 | `CUBRID Migration Toolkit` |
| 약어 | `CMT` |
| 금지 표기 | 마이그레이션 툴킷, CUBRID 마이그레이션 도구 모음, 큐브리드 마이그레이션 툴, CUBRID Migration Tool |

> 공통 규칙 18번 `툴킷 → 도구 모음`은 **제품 명칭에 적용하지 않습니다.**
> `CUBRID Migration Toolkit`을 `CUBRID Migration 도구 모음`으로 바꾸면 제품명이 훼손됩니다.
> 일반명사로 쓰인 `툴킷`만 `도구 모음`으로 수정합니다.

---

## 2. UI 라벨과 본문 용어 — 가장 주의할 항목

CMT 매뉴얼은 GUI 조작 절차 문서이므로 **제품 화면에 표시되는 문자열**과 **매뉴얼 표기 표준**이 충돌할 수 있습니다.

### 원칙

| 위치 | 처리 |
|:---|:---|
| UI 라벨 인용(버튼, 탭, 메뉴, 필드) | **제품 화면에 표시된 문자열 그대로.** 인라인 리터럴 또는 `:menuselection:`으로 감쌈 |
| 서술 문장 | **매뉴얼 표준 표기** 사용 |
| 첫 등장 | 표준 표기 뒤에 UI 라벨을 괄호로 병기 |

### 예시 — `컬럼` / `칼럼`

표준 표기는 `칼럼`(공통 규칙 2번)이지만 화면 라벨이 `Column` 또는 `컬럼`일 수 있습니다.

```rst
칼럼 매핑을 설정합니다. 객체 매핑 화면에서 ``Column``\ 을 선택하고,
매핑할 대상 칼럼을 지정합니다.
```

- 서술: `칼럼` (표준)
- 라벨 인용: `` ``Column`` `` (화면 원문)
- 라벨을 `칼럼`으로 바꾸도록 요구하지 않습니다.
- 반대로 **서술 문장에 `컬럼`이 남아 있으면 지적합니다.**

### 이미지 파일명

이미지 파일명은 경로이므로 표기 규칙 적용 대상이 **아닙니다.**
본문 표기를 `컬럼 → 칼럼`으로 바꾸면서 이미지 파일명까지 바꿀 필요는 없습니다.

단, 이미지 파일명을 변경했다면 이를 참조하는 모든 `.. image::` / `.. figure::` 지시자가
함께 갱신되었는지 반드시 확인합니다. **참조 누락은 빌드 경고와 깨진 이미지로 이어집니다.**

## 3. 표기 규칙을 적용하지 않는 대상

### 데이터 타입명

원본/대상 DBMS의 공식 타입 표기이므로 수정하지 않습니다.

- Oracle: `NUMBER`, `VARCHAR2`, `CLOB`, `DATE`, `TIMESTAMP`
- MySQL/MariaDB: `TINYINT`, `DATETIME`, `TEXT`, `ENUM`
- MS SQL Server: `NVARCHAR`, `MONEY`, `UNIQUEIDENTIFIER`
- CUBRID: `BIGINT`, `STRING`, `BLOB`, `DATETIMETZ`, `ENUM`

`appendix_typemap.rst`의 표 셀 값은 전체가 제외 대상입니다.
영문 규칙 18번 `datatype → data type`을 타입명·코드 식별자에 적용하지 않습니다.
단 서술 문장의 `데이타 타입`, `데이타형`은 `데이터 타입`으로 수정합니다.

### 접속 정보

JDBC 드라이버 클래스명, 접속 URL, 포트 번호
예: `com.mysql.cj.jdbc.Driver`, `jdbc:cubrid:localhost:33000:demodb:::`

### 설정·스크립트

마이그레이션 설정 XML/JSON의 요소명·속성명, 스크립트 파일명,
콘솔 실행 명령어(`migration.sh`, `migration.bat`)와 옵션

### 출력

마이그레이션 로그, 리포트 출력 예시 전체

## 4. 절차 문서 정합성

| 검토 항목 | 기준 |
|:---|:---|
| 단계 번호 | 문장을 추가·삭제·재배열하면 번호를 함께 갱신 |
| 이미지 대응 | 절차 단계와 참조 이미지의 화면이 일치 |
| 마법사 흐름 | `Next` / `Back` 이동 순서가 실제 화면 흐름과 일치 |
| 타입 매핑 | 본문 설명과 매핑 표의 대응 관계가 일치 |
| 상호 참조 | `:ref:` 타깃이 실제 존재하는 라벨 |

절차 재배열 시 번호·이미지·상호 참조 중 하나라도 누락되면 지적합니다.

## 5. 자주 발생하는 실수

| 상황 | 잘못된 수정 | 올바른 처리 |
|:---|:---|:---|
| 제품명 | `CUBRID Migration Toolkit` → `CUBRID Migration 도구 모음` | 제품명 원문 유지 |
| 타입 매핑 표 | `datatype` → `data type` (표 셀) | 표 셀은 원문 유지 |
| UI 라벨 | 화면 라벨 `컬럼` → `칼럼` | 라벨 원문 유지, 서술만 `칼럼` |
| 서술 문장 | `컬럼을 매핑합니다` 유지 | `칼럼을 매핑합니다`로 수정 |
| 이미지 | 본문 수정에 맞춰 이미지 파일명 변경 후 참조 미갱신 | 파일명 변경 시 모든 참조 지시자 갱신 |
| 접속 URL | `jdbc:cubrid:...`의 대소문자 변경 | 원문 유지 |
