제한 사항
============

* 호스트는 계정당 최대 400개까지 등록할 수 있다.
* 백업/복원/언로드/로드/생성 등 CMS의 오래 걸리는(async) 작업은 최대 12시간까지 진행 상태를 추적한다 (기본값,
  api-server의 ``CMS_JOB_LONG_TIMEOUT_HOURS`` 환경변수로 조정 가능). 그 이상 걸리면 더 이상 추적하지 않는다.

.. _unsupported-features:

미지원 기능
============

* Load Database 화면의 **"Trigger" 파일 선택 항목은 실제로 동작하지 않는다.** 화면에서 트리거 파일을 지정해도
  ``loaddb`` 에 전달되지 않아, 트리거는 이 화면으로 적재할 수 없다.
* 도움말 메뉴의 **업데이트 확인(Check for Updates)** 은 현재 비활성화되어 있다.

.. _known-bugs:

알려진 문제
============

* :ref:`auto-volume-log` 는 항상 빈 목록만 표시된다. 자동 볼륨 확장
  자체는 정상 동작하지만(볼륨이 실제로 생성됨), CMS가 이 로그를 기록하는 코드와 조회하는 코드의 필드 처리
  방식이 서로 어긋나 있어(볼륨 이름이 항상 빈 문자열로 기록되고, 조회 쪽은 필드 개수를 고정으로 가정하고
  읽어 시각(time) 자리에 엉뚱한 값이 들어감), 어떤 기간을 조회해도 결과가 항상 빈 목록으로 나온다 — NCA
  쪽에서 고칠 수 있는 문제가 아니라 CMS 자체의 결함이다.

주의사항
========

데이터베이스 유틸리티 동시 실행
--------------------------------

Manage Database의 각 작업은 CUBRID 엔진 자체의 제약을 그대로 물려받는다.

.. list-table::
    :header-rows: 1
    :widths: 45 55

    * - 작업
      - 동시 실행 시 동작
    * - Create / Copy / Rename / Restore / Optimize / Compact / Delete / Load Database
      - 오프라인 전용. 같은 데이터베이스에 대해 이미 다른 프로세스(콘솔 직접 실행 포함)가 이 중 하나를
        실행 중이면, 두 번째 시도는 에러로 안전하게 거부된다 (데이터 손상 없음).
    * - Unload / Check Database, Add Database Volume, Backup Database
      - 데이터베이스가 실행 중인 상태에서도 동시에 실행할 수 있으며, 무결성은 엔진의 트랜잭션과 락 관리에
        의존한다.
